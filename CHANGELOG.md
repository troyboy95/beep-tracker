# Changelog & Design Decisions

**Project context:** Beep Tracker is a live web tool that aggregates 200+ fresher job/internship posts in India from public, ToS-compliant sources. It deduplicates them, tags role and city with an LLM, and serves them on a searchable page that refreshes daily. Source brief: `plans/task.md`. Plan: `IMPLEMENTATION_PLAN.md`.

Newest entries on top.

| What | When | Why | Where |
|---|---|---|---|
| Phase 0 scaffold: `git init`, `db/schema.sql`, `.env.example`, `SOURCES.md`, `README.md`, pipeline package `beep` (typed settings, source contract, `doctor` checks, tests) | 2026-11-17 | Baseline repo. `doctor` gives a single command to verify all credentials and connectivity before Phase 1. | repo root, `db/`, `pipeline/` |
| **No ORM. SQL file is the schema source of truth. Web reads use `supabase-js` + generated types (Option A, chosen over Drizzle)** | 2026-11-17 | Drizzle is TS-only, but all writes come from the Python pipeline. Drizzle would mean two schema owners, and the trigger, `DISTINCT ON` view, generated tsvector and column grants would need custom migrations anyway. It would also need a direct DB password in Vercel instead of the RLS-guarded publishable key. `supabase gen types` gives type safety without that. | `db/schema.sql`, `web/` |
| Pipeline DB access: plain SQL via `psycopg` 3 over the Supabase **session pooler** | 2026-11-17 | Bulk `INSERT … ON CONFLICT` upserts are clearest in SQL. The pooler is IPv4, while the direct DB host is IPv6-only and GitHub runners can't reach it. | `pipeline/beep/`, `.env.example` |
| Cross-source dedup done in a `public_jobs` view (`DISTINCT ON dedup_key`, earliest seen wins) instead of deleting rows | 2026-11-17 | Keeps every source's row, which helps auditing and failover if one source drops a post. The public page still shows one row per job. | `db/schema.sql` |
| LLM ledger made append-only by a DB trigger (bypass only with `SET LOCAL app.ledger_maintenance='on'` for retention) | 2026-11-17 | Enforces the ledger guarantee in the database, not just by convention | `db/schema.sql` |
| Supabase default grants revoked. `anon` gets SELECT only on active jobs, the dedup view and non-sensitive `ingest_runs` columns. `llm_calls` is fully hidden. | 2026-11-17 | Supabase grants anon access to new public tables by default, so explicit revoke + RLS = least privilege | `db/schema.sql` |
| LLM model and per-token prices are env config (`GEMINI_MODEL`, `GEMINI_PRICE_*`), defaulting to `gemini-3.1-flash-lite` @ $0.25/$1.50 per M tokens (to be verified) | 2026-11-17 | Model releases and prices change often. Cost per 1k posts is computed from the configured prices with no code change. | `.env.example`, `pipeline/beep/config.py` |
| Adzuna attribution ("Jobs by Adzuna") required in the UI | 2026-11-17 | Adzuna API terms | `SOURCES.md`, `web/` (Phase 3) |
| `/plans` git-ignored (user); task brief copied into README | 2026-11-17 | Keep working notes private while reviewers still see the brief | `.gitignore`, `README.md` |
| **Added LLM ledger (`llm_calls` table)**: one append-only row per LLM call, holding the exact request, verbatim response, model, prompt version and hash, tokens, latency, cost, retries and errors. Each job links to its call via `jobs.tag_call_id`. | 2026-11-17 | Audit trail and reproducibility for every tag. Makes debugging "what broke" concrete for the video. Makes the point-3 cost exact (retries included). Lets each hand-check mismatch be traced to its raw model output. Hidden from the public (`anon` role) by RLS. | `db/schema.sql`, `pipeline/tagger.py`, `pipeline/ledger.py` |
| Created `IMPLEMENTATION_PLAN.md`, `CHANGELOG.md`, `PROMPT_LOG.md`, `.gitignore` | 2026-11-17 | Planning baseline, decision record, and session prompt log for the demo video | repo root |
| **Replaced the always-on FastAPI server on Oracle Cloud VM with a scheduled Python pipeline on GitHub Actions** | 2026-11-17 | The workload is a once-daily batch job, so a 24/7 server only adds ops burden (patching, TLS, uptime, Oracle idle-reclaim/capacity issues). Actions cron is free for public repos and logs every run. | `.github/workflows/daily-refresh.yml`, `pipeline/` |
| **Dropped the IP allow-list idea** | 2026-11-17 | Vercel serverless functions have no static egress IP on the free tier, so an allow-list would break the frontend → backend path. Security now comes from Postgres RLS (anon = read-only) and the service key living only in CI secrets. | `db/schema.sql` |
| Kept Python for the pipeline | 2026-11-17 | The original rationale for FastAPI (mature LLM SDKs, easy data wrangling) still applies; only the hosting model changed | `pipeline/` |
| Supabase Postgres (free) as the data store and pipeline↔web contract | 2026-11-17 | Unique constraints for dedup, built-in full-text search, run history table, and data refresh without redeploying the frontend. Daily writes stop the free-tier idle pause. | `db/schema.sql` |
| Next.js on Vercel reads the DB via server components + ISR + on-demand revalidation | 2026-11-17 | No separate API layer to maintain; pages stay fast and cached; the pipeline triggers revalidation so the UI updates right after each run | `web/` |
| Sources: Greenhouse, Lever, Ashby, SmartRecruiters public board APIs + Adzuna India API; no scraping of LinkedIn, Naukri or Internshala | 2026-11-17 | Greenhouse alone gives too few India-fresher posts to reach 200. All chosen sources are official public APIs, which meets the "respect each site's terms" requirement. | `pipeline/sources/`, `SOURCES.md` |
| Deterministic India + fresher pre-filters before the LLM | 2026-11-17 | Cuts LLM calls (cost) and noise. The LLM still confirms `is_fresher`. | `pipeline/normalize.py` |
| Two-layer dedup: exact `(source, external_id)` + cross-source `dedup_key = hash(company+title+city)` | 2026-11-17 | Handles re-fetches and the same role posted on several boards without fuzzy-matching complexity | `pipeline/dedup.py`, `db/schema.sql` |
| LLM: Gemini Flash-class model, ID pinned via env var; JSON-schema output with fixed role/city enums; batched calls; tag only new/changed posts (content hash) | 2026-11-17 | Enums make tags consistent and easy to evaluate. Batching and caching keep cost per 1k posts low. The env var guards against model deprecation. | `pipeline/tagger.py` |
| Token usage + estimated cost logged per run in `ingest_runs` | 2026-11-17 | Cost per 1,000 posts (task point 3) comes straight from data, not estimates | `pipeline/db.py`, `db/schema.sql` |
| Soft-expire posts not seen in the latest run (`is_active=false`) | 2026-11-17 | Keeps listings fresh without losing history; safe if a source temporarily fails | `pipeline/run.py` |
| Point 3 (evaluation) planned but not executed in this phase | 2026-11-17 | Per instruction; sampling script and cost formula are designed in the plan | `IMPLEMENTATION_PLAN.md` §6 Phase 5 |

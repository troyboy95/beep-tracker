# Changelog & Design Decisions

**Project context:** Beep Tracker is a live web tool that aggregates 200+ fresher job/internship posts in India from public, ToS-compliant sources. It deduplicates them, tags role and city with an LLM, and serves them on a searchable page that refreshes daily. Source brief: `plans/task.md`. Plan: `IMPLEMENTATION_PLAN.md`.

Newest entries on top.

| **Durable tagging queue** on `jobs` (`tag_status` pending/done/failed, `tag_attempts`, `next_tag_at`, `last_tag_error`). The worker (`beep/tag_queue.py`) honors the 429 `retryDelay`, stops at once when the *daily* quota is exhausted, trips a circuit breaker after 4 consecutive transiently-failed batches, backs off failed items (30 min transient / 2 h bad output), and parks an item as `failed` after 3 bad-output attempts. Transient errors never count as failures. Replaces the in-run deferred retry pass. | 2026-11-18 | User request: free-tier rate limits must not lose work, and pending items must be remembered across runs/deploys. State lives in Postgres, so nothing extra to run (no Redis/SQS). Verified: 45 posts left by 503s were drained by a `--tag-only` run (queue 45 → 0, public listings 242 → 277). | `db/migrations/003_tag_queue.sql`, `pipeline/beep/tag_queue.py`, `pipeline/beep/db.py` |
| `--tag-only` run mode (`ingest_runs.mode = 'tag_only'`) to drain the queue without re-fetching sources; to be scheduled several times a day in Phase 2 | 2026-11-18 | Spreads LLM calls across the day under free-tier RPM/RPD limits; cheap (no source traffic) | `pipeline/beep/run.py` |
| Prompt-version bumps re-queue `done` posts (`requeue_stale_prompt`) instead of a special query path | 2026-11-18 | One queue, one code path | `pipeline/beep/db.py` |
| Kept `bigint` identity PKs (no UUIDs) | 2026-11-18 | No distributed/client-side ID generation and no cross-DB merges, so UUIDs add nothing. Sequential keys give smaller, better-clustered indexes. `int4` would fit current volume, but `bigint` costs 4 B/row and avoids a lock-heavy type migration of every FK and `llm_calls.job_ids bigint[]` (the append-only ledger grows fastest). It's the Postgres/Supabase default. If non-enumerable public IDs are ever needed, add a UUIDv7 column. | `db/migrations/001_init.sql` |
| Measured cost (runs 1–3): 60 LLM calls (28 failed 503s at $0), 134k input / 32k output tokens, $0.0815 total → **$0.178 per 1,000 posts** at paid-tier prices | 2026-11-18 | Point 3 baseline, from the ledger (`python -m beep.ledger --cost`) | `llm_calls` |
| **Gemini 503 "high demand" → bounded retries + deferred retry pass**. Each batch gets 3 transient retries with exponential backoff (10/20/40 s). Batches still failing are retried once more after a 90 s wait at the end of the run. Anything left stays untagged and the next run picks it up. No fallback model. | 2026-11-18 | *What broke:* the first full run hit repeated 503s from the provider, and 2 batches (30 posts) failed after all retries. A fallback model would mix models and prices, muddying the accuracy and cost numbers in point 3. Every attempt is recorded in the ledger. | `pipeline/beep/run.py` |
| **Prompt v2** (tag-quality fixes from a manual review of the first 30 tags). `location` field is authoritative for city. Explicit city mapping, with "Other (India)" only for unlisted cities. `is_fresher` defined as *minimum* required experience ≤ 2 yrs, with examples. Role "DevOps & Cloud" renamed "DevOps, Cloud & IT". | 2026-11-18 | *What broke:* in v1, a Bangalore role was tagged Pune (from description text), a Chennai role was tagged "Other (India)", and "2+ yrs"/"1–3 yrs" roles were marked non-fresher, contradicting the 0–2 yrs rule. | `pipeline/beep/tagger.py` |
| Automatic re-tag on prompt version change (`tag_prompt_version` ≠ current → re-queued, capped by `MAX_TAG_PER_RUN`) | 2026-11-18 | Changing the prompt must not leave old-version tags live. The ledger keeps both versions' outputs for comparison. | `pipeline/beep/db.py` |
| Pre-filter fix: a stated minimum > 2 yrs now overrides generic fresher words in the *description* (title signals still win) | 2026-11-18 | *What broke:* "Legal Entity Controller (9 yrs)" and "Recruiter (8 yrs)" passed because their descriptions mentioned "campus"/"internship". This cut LLM input from 501 to 450 posts. | `pipeline/beep/normalize.py` |
| **Fresher definition widened to 0–2 years**, judged from the description, not just the title. Deterministic pre-filter: drop senior titles and stated minimums > 2 yrs. Keep explicit signals, ≤ 2 yrs, or no stated years. The LLM makes the final `is_fresher` call. | 2026-11-18 | User decision. Title-only matching found ~51 fresher posts across 2,423 India posts, far short of 200. The description-based 0–2 yrs rule gives ~450 candidates for the LLM. | `pipeline/beep/normalize.py`, `tagger.py` |
| **Dropped Adzuna**. Sources are the 4 public ATS APIs only. Expanded the board list via a probe script (~400 candidate tokens → 68 boards with India posts). | 2026-11-18 | User decision. Keeps every source first-party (employer boards). Volume comes from the wider fresher rule plus more boards. | `SOURCES.md`, `pipeline/beep/sources/companies.toml`, `pipeline/scripts/probe_boards.py` |
| Source adapters take a cheap title pre-check (`title_may_be_fresher`). SmartRecruiters detail requests only run for posts that pass it. | 2026-11-18 | SmartRecruiters needs one request per post for the description. Skipping obviously senior titles cuts that by ~65%. | `pipeline/beep/sources/adapters.py` |
| Per-board soft-expire: posts are deactivated only for boards that fetched successfully this run. Added `jobs.board`. | 2026-11-18 | One board's outage must not wipe its listings from the site | `db/migrations/002_phase1.sql`, `pipeline/beep/db.py` |

| **No ORM. SQL file is the schema source of truth. Web reads use `supabase-js` + generated types (Option A, chosen over Drizzle)** | 2026-11-17 | Drizzle is TS-only, but all writes come from the Python pipeline. Drizzle would mean two schema owners, and the trigger, `DISTINCT ON` view, generated tsvector and column grants would need custom migrations anyway. It would also need a direct DB password in Vercel instead of the RLS-guarded publishable key. `supabase gen types` gives type safety without that. | `db/schema.sql`, `web/` |
| Pipeline DB access: plain SQL via `psycopg` 3 over the Supabase **session pooler** | 2026-11-17 | Bulk `INSERT … ON CONFLICT` upserts are clearest in SQL. The pooler is IPv4, while the direct DB host is IPv6-only and GitHub runners can't reach it. | `pipeline/beep/`, `.env.example` |
| Cross-source dedup done in a `public_jobs` view (`DISTINCT ON dedup_key`, earliest seen wins) instead of deleting rows | 2026-11-17 | Keeps every source's row, which helps auditing and failover if one source drops a post. The public page still shows one row per job. | `db/schema.sql` |
| LLM ledger made append-only by a DB trigger (bypass only with `SET LOCAL app.ledger_maintenance='on'` for retention) | 2026-11-17 | Enforces the ledger guarantee in the database, not just by convention | `db/schema.sql` |
| Supabase default grants revoked. `anon` gets SELECT only on active jobs, the dedup view and non-sensitive `ingest_runs` columns. `llm_calls` is fully hidden. | 2026-11-17 | Supabase grants anon access to new public tables by default, so explicit revoke + RLS = least privilege | `db/schema.sql` |
| LLM model and per-token prices are env config (`GEMINI_MODEL`, `GEMINI_PRICE_*`), defaulting to `gemini-3.1-flash-lite` @ $0.25/$1.50 per M tokens (to be verified) | 2026-11-17 | Model releases and prices change often. Cost per 1k posts is computed from the configured prices with no code change. | `.env.example`, `pipeline/beep/config.py` |
